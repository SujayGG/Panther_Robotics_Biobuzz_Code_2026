# Android Studio setup

One-time setup for every programmer on the team.

## 1. Install the tools

| Tool | Notes |
|---|---|
| [Android Studio](https://developer.android.com/studio) | **Ladybug (2024.2) or newer** — the FTC SDK requires it |
| [Git](https://git-scm.com/downloads) | For cloning this repo |
| [Node.js 18+](https://nodejs.org) | Needed by the `ftc` MCP server (`npx`) |

A JDK ships inside Android Studio, so you don't need to install Java separately.

## 2. Clone the repo

```bash
git clone https://github.com/SujayGG/Panther_Robotics_Biobuzz_Code_2026.git
cd Panther_Robotics_Biobuzz_Code_2026
```

Clone it somewhere with a short path and no spaces or accented characters —
Gradle on Windows is fussy about that. `C:\FTC\` is a good choice.

## 3. Open it in Android Studio

**File → Open**, select the repository folder (the one containing
`settings.gradle`), and click OK. Do **not** use "Import Project".

Android Studio will now:

1. Ask to trust the project — say yes.
2. Run a Gradle sync, downloading Gradle and the FTC SDK libraries. The first
   sync takes several minutes; later ones are seconds.
3. Possibly prompt to install a missing SDK platform or build-tools version —
   accept.

`local.properties` is generated by Android Studio and is gitignored. Never
commit it; it holds a machine-specific path to the Android SDK.

If the sync fails, **File → Invalidate Caches → Invalidate and Restart** fixes
most of it. If Gradle can't reach the network, check you're not on a school
network that blocks Maven Central.

## 4. Build

From the terminal:

```bash
./gradlew assembleDebug        # macOS / Linux
gradlew.bat assembleDebug      # Windows
```

Or in Android Studio, **Build → Make Project** (Ctrl/Cmd + F9).

A successful build means the code compiles. It does not mean the robot works —
that still needs a test on the field.

## 5. Deploy to the robot

### Control Hub (over Wi-Fi)

1. Power on the Control Hub.
2. Connect your laptop to the hub's Wi-Fi network (SSID is on the hub, password
   is set in the Robot Controller app).
3. Connect and install:

   ```bash
   adb connect 192.168.43.1:5555
   adb devices                 # should list 192.168.43.1:5555  device
   ./gradlew installDebug
   ```

### Robot Controller phone (over USB)

1. Enable **Developer options** and **USB debugging** on the phone.
2. Plug it into your laptop and accept the debugging prompt on the phone.
3. `adb devices` to confirm, then `./gradlew installDebug`.

In Android Studio you can also just press the green **Run** button with
`TeamCode` selected as the run configuration.

`adb` lives in the Android SDK's `platform-tools` directory. If the command
isn't found, add that directory to your `PATH`:

- **Windows:** `%LOCALAPPDATA%\Android\Sdk\platform-tools`
- **macOS:** `~/Library/Android/sdk/platform-tools`
- **Linux:** `~/Android/Sdk/platform-tools`

## 6. See your OpModes

On the Driver Station, pick your OpMode from the TeleOp or Autonomous dropdown.
If it isn't listed:

- Check the class has an `@TeleOp` or `@Autonomous` annotation.
- Check it isn't marked `@Disabled`.
- Check the install actually succeeded and the Robot Controller restarted.

## 7. Watch the logs

```bash
adb logcat -s RobotCore:V System.err:V
```

Crashes and stack traces from your OpMode show up here — this is the fastest
way to debug a robot that stops mid-match.

## Working alongside Claude Code

Android Studio and Claude Code edit the same files on disk, so run them side by
side: Claude Code in a terminal for writing and refactoring code, Android Studio
for syncing Gradle, deploying, and reading logcat.

After Claude changes a Gradle file, hit **Sync Project with Gradle Files** (the
elephant icon) in Android Studio so the IDE picks the change up. Android Studio
reloads Java edits from disk on its own.

See [MCP_SETUP.md](MCP_SETUP.md) for the AI side of the setup.
